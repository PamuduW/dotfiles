## Summary
- **Most important (high):** `dotfiles full-update` approves the "Back up local work and replace it with upstream?" prompt on its own. A Dotfiles or dotfiles-shared checkout that has uncommitted changes or unpushed commits gets stashed and hard-reset to `origin` without asking. `docs/updates.md:38` says that replacement "requires approval".
- **Second (medium):** Agentbot writes `approvals_reviewer = "auto_review"` into every Codex config. That hands Codex's approval prompts to a reviewer agent, and no Agentbot document records the decision.
- **Counts:** critical 0, high 1, medium 5, low 8.
- The budget did not run out: about 10 external pages were used. Several checklist items were skipped to keep the review in one sitting; they are listed under "Not reached".
- **One deviation from the read-only rule:** a shell redirect created a scratch file, `/tmp/.r`, outside every repository. Nothing in any checkout or config was changed.

## dotfiles

### Defects
**`full-update` stashes and resets a dirty or ahead checkout without asking** — high
- Evidence: `scripts/lib/full_update.sh:4-6` defines `_dotfiles_approve_repo_update() { return 0; }`. `scripts/lib/full_update.sh:358` passes it as the gate's confirm function. In the shared state machine, `dotfiles-shared/scripts/lib/shared/repo_update.sh:333-341` routes the dirty, ahead and diverged states to `replace-local`. `_repo_update_replace_with_upstream` (`repo_update.sh:422-446`) then runs `stash push --include-untracked`, creates a recovery branch and runs `reset --hard @{upstream}`.
- Against the docs: `docs/updates.md:38` says "Dirty, ahead, and diverged replacement requires approval". Step 1 of the full-update section (`docs/updates.md:83`) only mentions restarting "if either moves forward".
- Tests: no test covers full-update meeting a dirty checkout. `tests/test_full_update.sh:327-339` only checks that the approver is passed.
- Impact: the recovery branch and stash keep the work, but the operator's in-progress edits disappear from the working tree. `bootstrap.sh:202` refuses a dirty checkout; full-update does not.
- Fix: make `_dotfiles_approve_repo_update` return 1 for the `replace-local` event, so the gate stops and reports, and only auto-approve `pull-behind` and `continue-ahead`.

**Registry "every component needs a probe" check can never fail** — low
- Evidence: `scripts/lib/components/registry.sh:321-322` accepts a key when `_comp_probe_<key>` exists **or** when `comp_probe` exists. `comp_probe` is defined unconditionally in the same file (`registry.sh:494`). Nine keys (nodejs, docker, lazygit, cursor_cli, claude_cli and others) get their probes from the generated `eval` at `probes.sh:444`, and nothing would notice if that generation stopped.
- Fix: delete the `|| declare -F comp_probe` alternative.

**Stale comments about the contract rule and the gate scope** — low
- `scripts/lib/shared_resolve.sh:24-25` says "The two must match exactly; a mismatch is a loud stop". The code at lines 80-95 and `dotfiles-shared/docs/consuming.md` both check "at least". The same file is copied verbatim into Agentbot with the same comment.
- `scripts/lib/repo_update.sh:28` and `:75` say "a full run on three", but `dotfiles_repo_gate` only gates `shared` and `own`.
- `.github/workflows/validate.yml:43` says "Weekly only", but the job runs on the daily cron. Line 76 says "three repositories" and checks two.
- Fix: correct the comments.

### Security
**lazydocker extracts the whole archive with no member check** — low
- Evidence: `scripts/lib/installers/github_release.sh:94` runs `tar -C "$tmp" -xzf "$tmp/$tarball"`. The archive is checksum-verified, but it is extracted without the escape check that `release_cli.sh:123-131` applies. GNU tar's default `../` stripping is the only guard. lazygit extracts a single named member (line 48).
- Fix: extract only the `lazydocker` member, as the lazygit path does.

The vendor shell installers (Claude, Cursor, Codex, direnv, nvm) are not checksum-pinned. `docs/security.md` records this as a decision, so it is not reported.

### Security
**Codex approvals go to an automated reviewer, and nothing records that decision** — medium
- Evidence: `cli/codex.config.toml:5` sets `approvals_reviewer = "auto_review"`, and the live `~/.codex/config.toml:1` carries it. Searching every Agentbot and Dotfiles doc for `approvals_reviewer` or `auto_review` finds no match. `docs/cli-config.md` documents the Antigravity and Remote Control choices but not this one.
- What the setting does: OpenAI's auto-review page says it "routes that approval request to a separate reviewer agent instead of stopping for a person". That covers escalated shell commands, blocked network requests, edits outside writable roots and MCP tool approvals. It cannot widen the sandbox. Source: learn.chatgpt.com, page undated, fetched 2026-10-13; confidence high, because it is the vendor's own page.
- The checklist asks for exactly this case: a setting that approves actions on the operator's behalf without a recorded decision.
- Fix: record the decision and its reason in `docs/cli-config.md`, or set the value back to `"user"`.

**Boost's PreToolUse hook is still registered on Bash with CLI filtering off** — low (suspected)
- Evidence: the live `~/.claude/settings.json` runs `boost-hook-claude.sh` on PreToolUse for `Bash|PowerShell|Read`. `src/boost.py:115-121` turned `boost-cli-filtering` off because that hook answered `permissionDecision: "allow"`.
- To confirm: in a scratch HOME, feed the hook a Bash PreToolUse payload and check that it emits no `permissionDecision`.
- Fix: if it still answers, have Agentbot drop Bash from the PreToolUse matcher.

**The live MCP-descriptor job installs unpinned dependencies with a secret in scope** — low
- Evidence: `.github/workflows/test.yml:93-100` installs `requirements*.txt` by range (`mcp>=2.2,<3`, `httpx>=0.28,<1`) without hashes. The `MCP_GITHUB_TOKEN` secret is only in the next step's environment. The packages installed in the step before it run inside that step.
- The step also exits 0 when the secret is missing, so the gate reads as passed.
- Fix: install from a hash-pinned lock, and print a warning annotation instead of exiting 0 silently.

## Needs human judgment
1. **Fine-grained GitHub tokens skip the read-only scope check.**
   - Background: `github_token.sh:31-34` treats a missing `X-OAuth-Scopes` header as "unknown, not refused". A fine-grained token with write permission is therefore saved and exported to every shell as `GITHUB_MCP_TOKEN` (`bash/.bashrc:165`). Every agent's shell, and every `npx` it runs, inherits it.
   - Options: (a) keep as is; (b) refuse tokens without scopes unless the operator confirms; (c) probe one write endpoint and expect a 403.
   - Recommendation: (b).
2. **Antigravity's live `toolPermission` is `"always-proceed"`** (`~/.gemini/antigravity-cli/settings.json:7`).
   - Background: the docs keep this setting per machine, and on this machine `agy` runs shell commands without asking.
   - Options: keep it, or set "ask".
   - Recommendation: ask, so Antigravity matches the other three clients' review layer.
3. **akindu-agent-skills has no licence.**
   - Options: keep using it, ask the author for a licence, or fork the skills you use into `agentbot_skills`.
   - Recommendation: ask the author.
4. **Codex `auto_review`.**
   - Options: record it as a decision, or revert it to `"user"`.
   - Recommendation: record it with its reason. It is a reviewer, not a bypass, but it is a decision.
